PROGETTO 1 - LANDING PAGE AD ALTA CONVERSIONE
====================================================================
Nome portfolio:
Conversion Landing for Local Service

Problema da risolvere:
Piccole attivita locali hanno traffico ma pochi contatti qualificati.

Target utente:
- Professionisti locali (studio medico, avvocato, consulente)
- Utente che arriva da Google o ads e deve contattare in pochi secondi

MVP (ready to build):
- Hero con value proposition chiara
- Sezione servizi breve e orientata a benefici
- Testimonials / proof
- FAQ
- CTA primaria sempre visibile
- Form contatto con validazione
- Tracking eventi (CTA click, form submit)
- Performance base (Lighthouse > 90)

Extra (fase 2):
- A/B test su headline
- Sticky CTA mobile
- Calendly embed
- Heatmap (Hotjar o equivalente)

Stack consigliato:
- Next.js, TypeScript, SCSS Modules
- Form: React Hook Form + Zod
- Analytics: GA4 + eventi custom

Data model minimo:
- leads(id, name, email, phone, service_interest, source, created_at)

API endpoints:
- POST /api/leads
- GET /api/leads (admin)

KPI da mostrare nel case study:
- Conversion rate form
- CTR CTA principale
- Tempo medio sulla pagina

Roadmap sviluppo:
- Giorno 1-2: wireframe + copy structure
- Giorno 3-4: build UI responsive
- Giorno 5: tracking + form backend
- Giorno 6: ottimizzazione performance
- Giorno 7: QA e deploy

Definition of done:
- Mobile perfetto
- Eventi tracciati correttamente
- Form con feedback error/success
- Punteggio Lighthouse >= 90

PROGETTO 3 - WEB APP GESTIONALE CRUD CON RUOLI
====================================================================
Nome portfolio:
Client & Orders Manager

Problema da risolvere:
Gestione manuale clienti/ordini su fogli e chat, alto rischio errore.

Target utente:
- Team operativo piccolo (2-10 persone)

MVP:
- Login/logout
- Ruoli (admin, operator)
- CRUD clienti
- CRUD ordini con stato (nuovo, in lavorazione, chiuso)
- Ricerca, filtri, ordinamento
- Storico modifiche base

Extra:
- Export CSV/PDF
- Commenti interni per ordine
- Notifiche email su cambio stato

Stack:
- Next.js + TypeScript
- DB: PostgreSQL
- ORM: Prisma
- Auth: NextAuth/Auth.js

Data model:
- users(id, name, email, role)
- clients(id, name, email, phone, company)
- orders(id, client_id, amount, status, assigned_to, created_at)
- order_logs(id, order_id, action, user_id, created_at)

API endpoints:
- /api/auth/*
- /api/clients (GET/POST)
- /api/clients/:id (GET/PATCH/DELETE)
- /api/orders (GET/POST)
- /api/orders/:id (GET/PATCH/DELETE)

KPI case study:
- riduzione tempo gestione pratiche
- riduzione errori inserimento
- tempo medio per trovare ordine

Roadmap:
- Settimana 1: auth, schema DB, CRUD clienti
- Settimana 2: CRUD ordini, filtri, ruoli, audit

Definition of done:
- Permessi rispettati
- Nessun dato sensibile esposto client-side
- Flussi CRUD completi e testati

PROGETTO 6 - AUTOMAZIONE WORKFLOW END-TO-END
====================================================================
Nome portfolio:
Lead Automation Pipeline

Problema:
Lead raccolti manualmente e follow-up incoerente.

Target:
- Freelance/agenzie con lead generation da sito

MVP:
- Form sito -> webhook
- Salvataggio lead su DB/CRM
- Email automatica di conferma
- Task interno creato automaticamente
- Dashboard minima stato lead

Extra:
- Scoring lead
- Reminder follow-up automatico
- Slack/Telegram notifications

Stack:
- Next.js
- n8n/Make/Zapier (oppure workflow custom)
- SMTP/Resend

Data model:
- leads(id, name, email, source, score, status)
- tasks(id, lead_id, assignee, due_date, status)
- automation_logs(id, lead_id, step, success, created_at)

API:
- POST /api/webhooks/lead
- GET /api/leads/pipeline

KPI case study:
- tempo medio lead->contatto
- % lead contattati entro 24h
- riduzione lead persi

Roadmap:
- Giorno 1-2: flusso eventi
- Giorno 3-4: integrazioni email/task
- Giorno 5: dashboard pipeline
- Giorno 6-7: hardening e retry logic

Definition of done:
- Ogni step tracciato
- Retry su errori temporanei
- Nessuna perdita silenziosa lead
